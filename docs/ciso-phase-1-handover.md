# SORP 2026 — CISO Phase 1 closure and handover

**As at 24 October 2026 (Africa/Kampala).** This closes the focused remediation phase, not the security review or commercial approval. No authentication cutover, customer migration, or production change is authorised by this document.

## Baseline and current judgement

The original CISO assessment gave a **provisional 41/100**. Its principal concerns were the unintended SORP → My Social Impact (MSI) → Cow account chain; vulnerable dependencies; unverified email ownership and founder MFA; weak assurance over tenant, charity and adviser permissions; database privilege and audit integrity; incomplete backup/recovery; and gaps in monitoring, secret separation, file handling and UK data governance. The full original scoring worksheet is not retained here, so the comparison is a professional estimate, not a repeat of the original audit.

**Current live maturity: provisional 60/100, revised from 55/100 after the live broker patch below.** SORP's vulnerable Next.js release was replaced, its complete Neon application backup was restored in isolation, and MSI's critical-rated Next.js dependency is now patched in production. Focused security tests improved. The larger authentication and permission redesign earns little *production* credit while cutover is off. Live login still depends on MSI/Cow. The five-point revision reflects one verified live dependency fix, not a new full audit; this score is neither certification nor evidence of safe commercial expansion.

**CISO decision:** Phase 1 can pause and UX/UI and standalone-product due diligence can proceed. The identified live MSI Next.js critical dependency is patched; no exploit or breach was demonstrated. SORP is still not CISO-approved for independent authentication or full commercial launch.

## Live MSI broker critical dependency — resolved in production

The former **live MSI** deployment `dpl_7TngkNVn7PzU8MYbPfCuCV8GrGiE` used Next.js **16.2.6** in its package and lockfile. Its exact-lockfile `npm audit --omit=dev` reported **one critical and four high** findings, including conditional unauthenticated RCE advisories such as [GHSA-2464-fhr4-w9xw](https://github.com/advisories/GHSA-2464-fhr4-w9xw). No exploit or breach was demonstrated. MSI's `images.unoptimized: true`, lack of `next/og` or `use cache` use, and Vercel's non-Windows runtime limited some paths, but did not justify leaving a vulnerable account broker deployed.

[MSI PR #8](https://github.com/mysocialimpact/my-social-impact/pull/8) pinned Next.js and its matching lint package to **16.4.3**, updated the lockfile and added a mocked signup/login/session/logout regression test. Focused account and OAuth tests passed **18/18**; recovery cases covered the read-only status, request forwarding, reset cookie and failure handling without sending mail. The patched production-dependency audit fell to **zero critical, one high, one moderate**. The wider MSI suite retained the same **12 pre-existing content-test failures** as baseline (patched 85/97; baseline 84/96), and lint retained the same six baseline errors. Local `next build` failed to fetch Google Fonts under this workspace's network policy on **both** versions; Vercel's preview and production Next builds succeeded.

MSI production deployment `dpl_xYtfdvTfpz8CDdFninP9qzr5t3xB` is **READY**, aliased to `mysocialimpact.org`, at merge commit `926242b8`; its build log identifies Next.js **16.4.3**. Live read-only requests returned `{"signedIn":false}` for an anonymous session and `{"available":true}` for password-recovery capability, both with `Cache-Control: no-store`. Real customer registration, login, password reset and email delivery were **not** exercised; these retain the prior Cow service and require final acceptance before broader growth. No customer email was sent.

## Technical due diligence handover and final approval

The current production identity path remains **SORP → MSI broker → Cow account service/D1**. Other SORP routes use MSI for booking, payments, public readiness research, transcription, report delivery and Ask SORP; `growth-click` can call Cow directly. Some Ideas Shed branding/assets and links are externally referenced. The new due-diligence thread must inventory each runtime and data dependency, ownership, credentials, processor exposure, failure mode and transfer route before calling SORP self-contained. Do not remove shared credentials or infrastructure during authentication preparation.

Return for final CISO approval only after independent auth is configured and tested end to end with approved addresses, founder MFA and tenant/permission gates pass in production-equivalent conditions, Neon and Cow recovery paths protect existing work, critical CI/browser checks pass, a controlled rollback is rehearsed, and the founder explicitly authorises cutover. An independent penetration test and UK privacy/legal review remain separate assurance steps. Preserve Cow/MSI records throughout.
